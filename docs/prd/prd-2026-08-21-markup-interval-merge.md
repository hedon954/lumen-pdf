# LumenPDF — 划线区间合并 PRD

## 1. 产品结论

在已有划线附近再划一段新区域时，未选中的旧划线必须保持不动。重叠、合并和取消只按**同一文本行上的水平区间**计算，不能把多行选区收成一个大矩形去撞上一行。

## 2. 问题

用户先给一段连续正文划线，再给紧挨着的下一段划线或高亮时，中间未选中的行会被整段抹掉。原因是旧实现用整段选区的包围盒判断「碰到了已有标注」，相邻行的 PDF 行框往往还有几磅垂直重叠，于是上一行也被当成冲突对象删掉，再只把新选区画回去。

## 3. 功能需求

### F1 — 未选中的行不受影响

- 新选区与已有自由划线/高亮没有同一行上的水平相交或紧邻时，只新增，不改动旧标注。
- 即使新选区包围盒与上一行的行框相交，只要不是同一文本行，也不算重叠。

### F2 — 同行才合并或取消

- 同一行上区间相交或间距不超过一个普通词距：把该行合成一条，其它行保持原样。
- 新选区的每一行都已经被已有同类型标注盖住：只取消选中的那一段，未选中的左右或上下剩余保持。
- 新选区只有部分行或一行里只有一部分是新的：与碰到的已有区间做并集，不丢弃未碰到的行。

### F3 — 高亮与划线同一套规则

- 自由高亮（`__fh`）和自由划线（`__fu`）使用同一套行区间规则，互不影响。
- 不改变笔记条目的合并产品语义，只统一底层矩形合并。

## 4. 非目标

- 不引入按字符偏移的 PDF 文本层坐标系统。
- 不把划线改成独立窗口或第三方标注引擎。
- 不修改单词本高亮（按条目 UUID 标记的那些）。

## 5. 验收标准

1. 先划连续多行，再划其下方紧邻的新区域：原来的中间行仍在，新区域也有划线。
2. 在已有划线的同一行上向右延长：该行连成一条，其它行不变。
3. 重新选中已经完全划过的区域再点划线：只去掉这段，旁边未选中的划线还在。
4. 新选区与旧划线完全不相邻：两者并存。
