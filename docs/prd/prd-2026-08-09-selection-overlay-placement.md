# LumenPDF — 选区浮层统一定位 PRD

**版本**: v1.0.21 · **日期**: 2026-08-09

## 1. 产品结论

文本选区触发的操作栏、翻译窗口、笔记编辑窗口和笔记回顾窗口必须遵守同一套位置原则：默认紧贴选区下方；下方空间不足时依次尝试上方、右侧和左侧；每个位置都必须尽量避免覆盖选区，并保持完整可见。

只有当选区本身过大、可视区域确实无法同时容纳选区与浮层时，才允许覆盖；此时应选择遮挡面积最小且离选区最近的位置，不能因为窗口边界钳制而跳到不符合用户预期的角落。

## 2. 问题

1. 双击单词或选择句子后，操作栏按一个预先计算的中心点显示，默认位于选区上方，并可能覆盖选区。
2. 笔记窗口虽然评估四个方向，但候选位置被钳制到窗口边界后，没有验证它是否仍位于声明的方向；名义上的“下方”位置可能已被挤到远处。
3. 浮层首次测量后会锁定方向。内容高度继续变化时，即使原方向开始覆盖选区，也不会重新避让。
4. 笔记编辑窗不启用点外关闭，因此没有全屏透明背景；旧外壳会先把卡片居中，再叠加定位偏移，造成卡片向右下角远离并被裁切。
5. 操作栏与窗口型浮层使用不同定位实现，规则会继续漂移。

## 3. 功能需求

### F1 — 统一优先级

- 所有选区浮层默认位于选区下方，并与选区保留小间距。
- 下方无法完整容纳时，按上方、右侧、左侧顺序寻找不遮挡位置。
- 横向只做保证浮层完整可见所需的最小移动，避免无理由贴到窗口左侧或右侧。

### F2 — 边界钳制后重新判定

- 候选位置限制到可视区域后，必须再次确认浮层仍完整位于对应方向。
- 被边界挤回选区内部的候选不得继续作为无障碍位置使用。
- 浮层内容尺寸改变后，已选方向若开始覆盖选区，必须重新评估其他方向。

### F3 — 不可避免的遮挡

- 当四个方向都无法无重叠放置时，优先选择遮挡面积更小的位置。
- 遮挡面积接近时，选择离选区更近、边界修正量更小的位置。
- 此路径只用于大选区或极小窗口等确实无法避让的情况。

### F4 — 展示边界

- 操作栏继续由阅读窗口根层 SwiftUI overlay 持有，确保可跨越左右侧栏且不被裁切。
- 窗口型浮层的坐标原点固定为阅读区左上角，不得依赖是否存在点外关闭背景来撑满容器。
- 不新增 `NSPanel`、子窗口或第二套坐标空间。
- 不改变翻译、高亮、划线、解释和笔记动作本身。

## 4. 验收标准

1. 页面中部双击单词或选择一句话，操作栏紧贴选区下方且不遮挡文字。
2. 靠近页面底部选择文本，下方空间不足时操作栏出现在上方。
3. 在窗口左右边缘选择文本，操作栏保持完整可见，并尽量与选区水平居中。
4. 打开添加笔记窗口时，窗口使用同一方向优先级，不再跳到远离选区的左下角。
5. 笔记或翻译内容变高后，原方向若无法继续避让，会切换到可用方向。
6. 选择大段文本导致四周空间不足时，浮层仍完整可见，并采用最小遮挡位置。
7. 点击、关闭、拖动、缩放和外部点击语义保持不变。
