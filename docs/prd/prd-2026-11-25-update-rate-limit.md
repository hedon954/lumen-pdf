# 检查更新失败时说明接口错误并可以重试

## 问题

手动检查更新遇到 GitHub 拒绝请求时，面板只写「无法连接更新服务」。额度用完、网关错误和真正连不上都是这一句，看不到接口自己返回的原因。失败后也没有就地重试，只能关掉再开一次。

## 用户行为

- 检查失败时，先给一句能读懂的说明，再原样附上接口错误。额度用完写「更新服务的请求次数已用完，请稍后再试。」连不上或收到其他 HTTP 失败仍写「无法连接更新服务。请稍后再试。」下面一行是状态码和接口的 `message`；没有正文时至少有 `HTTP` 和状态码。超时、解析失败也附上具体原因，不另造一套覆盖不全的文案。
- 这段文字可以选中复制。
- 失败面板提供「重试」，再次向官方发布查询。检查过程中按钮不可用。
- 已是最新、发现新版本时不出现「重试」。自动检查失败仍不弹面板。

## 非目标

不内置 GitHub token，也不自动等待额度恢复。不在提示里写出口 IP 或重置时刻，这些如果出现，只因为接口原文里有。

## 验收

1. 接口返回 403 且 `x-ratelimit-remaining` 为 0，或返回 429，或带 `retry-after` 时，说明是请求次数用完，并带上接口的 `message`。
2. 超时或其他 HTTP 失败仍说明无法连接，同时带上这次的具体错误，而不是只留一句固定话。
3. 失败面板可以点「重试」再查一次。
