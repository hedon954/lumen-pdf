# LumenPDF — LLM 服务商「其他」PRD

## 1. 产品结论

LLM 设置的服务商菜单必须提供「其他」，让用户指向任意 OpenAI 兼容（或现有协议）端点。选中「其他」不得用内置预设覆盖已经填写的 Base URL、模型或 Extra Config。当前地址对不上任何内置服务商时，菜单应显示「其他」，而不是给某个内置项打勾。

## 2. 问题

服务商列表只有内置厂商。用户要接自建网关、代理或名单外的兼容服务时，只能改 Base URL；菜单里看不到明确入口，也容易让人以为必须落在某个内置商上。

## 3. 功能需求

### F1 — 菜单里的「其他」

- 设置 → LLM 的「服务商」菜单在「内置服务商」列表之后提供「其他」。可用分隔分组，不把「其他」混进内置名单。
- 选择任一内置服务商时，仍按现有规则填入该服务商的 Base URL，并带上对应的模型历史与 Extra Config 默认值。
- 选择「其他」不得用任何内置预设覆盖当前 Base URL、模型、API Key 或 Extra Config。这些字段保持可编辑。
- 从「其他」改选某个内置服务商时，仍可应用该内置项的默认值。再选回「其他」时，不得清掉用户已经填过的自定义地址；应回到刚才那份自定义配置。
- 当前 Base URL 规范化后与所有内置地址都不相同，菜单显示「其他」，不得误选最接近的内置项。
- 「最近使用」里的自定义地址仍可作为快捷项；未匹配内置地址时，当前选中项是「其他」。

### F2 — Extra Config 与密钥

- 「其他」不另建一套设置系统。Extra Config 仍按当前 Base URL 隔离读写；未知主机沿用现有启发式：对不上厂商规则且模型名也不命中时，默认为空（未附加厂商字段）。已保存的 `{}` 仍表示不附加任何字段。
- API Key 仍按现有 Base URL 身份写入 Keychain，自定义地址与内置地址使用同一套规范化与别名规则。
- 当前地址未匹配内置服务商时，不显示官方 API Key 申请链接。

### F3 — 模型列表

- 自定义 Base URL 与有效 API Key 仍可请求 `{normalizedBaseURL}/models`。
- 「其他」不必出现在任何硬编码厂商目录里；模型过滤只在当前地址匹配到带前缀限制的内置项时生效。

## 4. 非目标

- 不把任意 URL 就近归到某个内置服务商。
- 不新增第二种 LLM 设置存储。
- 不要求用户从固定模型目录里挑选「其他」。
- 不改变翻译降级链或 chat 请求协议。

## 5. 验收标准

1. 服务商菜单在内置列表之后可以看到并选中「其他」。
2. 当前 Base URL 不是任何内置地址时，菜单勾选「其他」，而不是某个内置商。
3. 在已填写的自定义 Base URL / 模型 / Extra Config 上选择「其他」，这些字段不被重置。
4. 选择某个内置服务商后，Base URL 变成该预设地址，Extra Config 按该地址显示默认或已保存值。
5. 从自定义地址改选内置，再选回「其他」，原先输入的自定义 Base URL 仍在，没有被内置地址覆盖。
6. 自定义地址保存后，API Key 仍只按该 Base URL 身份出现在 Keychain；重启后能读回。
7. 自定义地址与有效 Key 可以刷新模型列表；刷新失败时仍可手动填写模型。
