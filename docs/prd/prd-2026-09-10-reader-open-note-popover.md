# 系统打开 PDF 与统一笔记浮窗

## 问题

从 Finder 选择 LumenPDF 打开 PDF 没有切换文档；翻译与笔记浮窗背景不一致；笔记回顾缺少直接追加入口，编辑后删除其他条目可能覆盖刚保存的内容。长音标会导致标题挤压和异常留白；局部笔记弹窗点外不关闭，容易与新选区操作栏重叠；尚未保存笔记的划线缺少笔记入口。

## 用户行为

- Finder「打开方式」、拖到应用图标等系统文件打开请求，应打开请求的 PDF 并切回 PDF 阅读页。应用冷启动时，指定文件优先于上次阅读文件。
- 切换前保存原文档的阅读位置；打开曾读过的文件时沿用已有恢复逻辑，恢复页码、缩放和横纵位置。重复打开当前文件不重新加载或跳回旧位置；无效文件不替换当前文档。
- 所有阅读弹窗共享同一呈现层与互斥规则。点击弹窗外的正文、目录、Inspector 或工具栏即关闭，并让原点击继续执行；新选区关闭旧弹窗，应用失焦关闭弹窗。点击弹窗内部不关闭；删除确认框不算外部点击。
- 翻译、添加笔记、回顾笔记统一使用带箭头的薄材质浮窗背景、圆角、细边框与阴影，随浅色/深色外观变化。翻译保留选区强调、指向箭头、拖动和已有宽高规则。
- 回顾笔记浮窗底部始终提供「添加新笔记」输入框和「添加」按钮。空白不能添加，成功清空输入并留在浮窗继续追加；失败保留输入并显示错误。
- 现有笔记直接编辑并自动保存，保留单条删除和「删除全部」。全部只指当前选区关联的笔记，不是整本 PDF 或全库。
- 编辑、追加、删除后浮窗与右侧笔记保持一致；删除单条不会覆盖其他已修改内容。删除最后一条时移除对应划线，当前选区无笔记后关闭浮窗。
- 翻译原文与音标自然换行，长音标不能挤掉单词、撑出大块空白或迫使卡片越界。
- 划线尚未填写笔记也显示笔记入口，点击直接添加；保存后同一位置切换为笔记回顾入口。跨页笔记在每个有划线的页面都保留入口。

## 非目标

不改存储格式、翻译字段和模型调用，不引入独立面板或子窗口。

## 验收

1. 打开 A 并滚动/缩放，系统打开 B，再打开 A，恢复 A 的位置；在单词本或笔记页接收文件时切回阅读。
2. 冷启动指定 B 不停留在历史 A；重复打开当前文件保持视口；无效 PDF 显示失败并保留当前文档。
3. 浅色和深色下比较翻译与笔记背景；检查左右边缘、点内/点外、第二次选区、滚动缩放、窗口移动缩放、应用切换。
4. 同一选区连续添加三条，修改第二条后删除第一条，第二条保留新内容；继续修改剩余条目后重新打开，顺序和内容正确。
5. 删除全部只清除当前选区；其他选区与其他文档的笔记保留。失败不丢弃新输入。
6. 重现长音标 implement 的窄浮窗、页尾划线无笔记、打开草稿后选择其他文字，分别确认标题完整紧凑、入口可用、弹窗互斥。
