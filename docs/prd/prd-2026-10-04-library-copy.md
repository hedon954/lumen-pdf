# 书库副本

## 问题

文库记的是原文件路径。原文件改名、移动或删除后，阅读进度、笔记和单词就和这本书断开了，阅读日志也会把它当成一本新书。

## 用户行为

- 打开或导入 PDF 时，LumenPDF 把文件复制到 `~/Library/Application Support/LumenPDF/Library/<书的 id>/<原文件名>`，之后读的都是这份副本。同一磁盘上用 APFS 克隆，几乎不占额外空间；不行时普通复制。原文件从不修改、移动或删除。
- 再次导入内容完全相同的文件（哪怕改了名字或换了位置）时，复用文库里已有的书，进度和标记都在。文件夹导入的提示把这类文件算作「已在文库中」。
- 同名但内容不同的文件算一本新书。
- 从文库移除一本书，或清空、撤回导入时，书库里的副本一并删除。笔记、单词和原文件保留；笔记指回原文件，从笔记再次打开会重新导入，笔记接回新的副本。后续修订：删除和清空会清掉这些书自己的笔记和单词语境；撤回导入仍然保留，见 [prd-2026-11-27-library-shelves.md](prd-2026-11-27-library-shelves.md)。
- 升级后第一次启动时自动迁移：先在 `data.db` 旁边留一份 `data.db.before-library-<时间>` 备份，再把文库里每本书复制进书库，并把笔记和单词一起改到副本上。笔记、单词、划线、阅读进度都不变。
- 迁移时原文件找不到的书留在文库里，标「找不到文件」，其余书照常迁移。之后原文件回来、再次打开时补做复制。

## 非目标

不在 Finder 里展示书库，不提供「在书库中显示」。不清理已经存在的重复书。不把笔记里的高亮写回 PDF。

## 验收

1. 打开一个 PDF 后改名原文件，文库里的书仍能打开，进度和笔记都在。
2. 再导入同一个文件的拷贝，文库不增加条目。
3. 两个同名但内容不同的 PDF 在文库里是两本书。
4. 从文库移除一本书后，`Library/<id>/` 被删除，原文件还在，笔记还在。
5. 迁移后 `data.db` 旁有备份；所有笔记、单词、划线和阅读进度与迁移前一致；找不到原文件的书标「找不到文件」。
