# 检查更新和翻译跟随系统代理

## 问题

检查更新用的网络库只看进程环境变量，不看 macOS 系统代理。从访达打开应用时通常没有 `HTTPS_PROXY`。用户开着 Clash、Surge 或其他 VPN 的系统代理时，请求会绕过代理直连 GitHub。代理端口每家都不一样，也可能在应用已经打开之后才打开或关掉。

## 用户行为

- 检查更新、读取校验，以及翻译请求，都按这一刻的系统代理发出。不写死端口、软件名或某一种 VPN。
- 系统设置里的 HTTP 代理、HTTPS 隧道代理和 SOCKS 代理都会使用。开着哪一种就用哪一种；几种同时开着时，用系统给出的优先顺序。
- 环境变量 `HTTPS_PROXY`、`HTTP_PROXY`、`ALL_PROXY` 优先于系统代理。`NO_PROXY` 和系统代理排除名单里的地址直连，例如本机的模型服务。
- 没开代理时直连。只做全局隧道、没有系统代理项的 VPN，仍由系统路由，应用不额外指定代理。
- 使用自动代理脚本时，按系统算出的结果连接。
- 代理开、关或改端口之后，下一次请求就按新的设置，不用重新打开应用。

## 非目标

不在应用里填写代理主机和端口。不保存代理密码，也不读取钥匙串里的代理密码。不改下载安装包的方式，下载仍由系统网络栈完成。

## 验收

1. 系统 HTTPS 代理设在任意本机端口时，检查更新走这个端口，而不是直连。
2. 只开 SOCKS、端口与别人不同时，检查更新仍走该 SOCKS 代理。
3. 系统代理排除 `127.0.0.1` 时，发往本机的翻译请求不经过代理。
4. 设置了 `HTTPS_PROXY` 时用环境变量；目标在 `NO_PROXY` 里时直连。
5. 应用打开之后再打开或关掉系统代理，下一次检查按新的设置。
