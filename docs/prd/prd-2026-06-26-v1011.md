# LumenPDF — 产品需求文档 (PRD)

## 本次迭代概述 (v1.0.11)

本次 PR 聚焦阅读中“解释”和“翻译设置生效”的完整体验闭环：

1. 解释不再一点击就直接请求 AI，而是先让用户输入自己的疑问；无输入时仍支持直接解释。
2. 解释气泡需要随主窗口尺寸自适应，尤其高度必须按主窗口比例限制，超出内容可滚动。
3. 设置页的目标语言需要对应不同语言的 prompt；中文目标使用中文 prompt，英文目标使用英文 prompt。
4. 切换目标语言后，下一次 API 调用必须立即使用新语言，不要求用户额外保存。
5. 翻译缓存必须按目标语言隔离，避免 English 缓存污染中文翻译。
6. App 需要记住上次窗口大小和位置，减少每次打开后的手动调整。

## 新增 / 变更功能需求

### O24 — 先提问再解释的选区解释流程

**问题**：

原先点击「解释」会立刻请求 AI。用户希望先提出自己的疑问，再让 AI 围绕关注点解释；同时仍保留无需提问的快速解释能力。

**需求**：

- 用户点击选区菜单「解释」后，先弹出解释输入框，不立即请求 LLM。
- 输入框允许用户输入自己的疑问或关注点。
- 按钮文案根据 trim 后的输入动态变化：
  - 输入为空：显示「直接解释」
  - 输入非空：显示「解释」
- 用户点击按钮，或在输入框 / 解释前气泡获得键盘焦点时按回车后，才发起解释请求。
- 输入为空或仅包含空白字符时，按回车等同于点击「直接解释」。
- 有疑问时，AI 应先回答用户问题，再从第一性原理围绕该关注点展开。
- 无疑问时，AI 执行通用快速解释。

**验收标准**：

| 用例 | 期望行为 |
| --- | --- |
| 点击「解释」 | 只显示输入框和原文，不立即请求 AI |
| 输入全为空格 | 按钮显示「直接解释」 |
| 输入问题 | 按钮显示「解释」 |
| 输入问题后解释 | prompt 包含用户问题，输出围绕问题展开 |
| 不输入直接解释 | 走通用解释 prompt |
| 输入框聚焦且无输入时按回车 | 直接走通用解释 prompt |
| 输入框聚焦且有问题时按回车 | 等同点击「解释」，prompt 包含用户问题 |
| 解释前气泡被选中但输入框未聚焦时按回车 | 等同点击当前主按钮 |

### O25 — 解释气泡按主窗口比例限制尺寸并支持滚动

**问题**：

AI 解释可能很长，气泡高度如果跟随内容无限增长，会遮挡阅读区域甚至超出窗口。

**需求**：

- 解释模式气泡宽度和高度都基于当前阅读窗口尺寸计算。
- 解释窗口自动高度必须受主窗口高度比例限制。
- 解释内容超过限制后在气泡内部滚动，而不是继续撑高窗口。
- 用户手动 resize 时仍受当前窗口尺寸限制。
- 解释前的输入框 + 原文预览也要遵守同样的高度限制和滚动策略。

**验收标准**：

| 用例 | 期望行为 |
| --- | --- |
| 主窗口较小 | 解释气泡按比例缩小，不超出主窗口 |
| AI 输出很长 | 气泡高度保持受限，内容区域可滚动 |
| 原文很长但尚未解释 | 输入框 / 原文预览区域可滚动 |
| 用户拖拽调整气泡 | 最大尺寸仍受当前窗口限制 |

### O26 — 中英文两套 prompt 模板与语言切换

**问题**：

设置页目标语言切换后，prompt template 仍可能显示上一语言的模板，导致 English 下显示中文 prompt，或中文下显示英文 prompt。

**需求**：

- 设置页内置中文和英文两套 User Prompt / System Prompt。
- 目标语言为简体中文或繁體中文时，使用中文 prompt 默认值。
- 目标语言为 English 或其他非中文语言时，使用英文 prompt 默认值。
- 每个语言族单独保存用户自定义 prompt。
- 切换语言时：
  1. 保存当前语言族的 prompt；
  2. 加载目标语言族已保存 prompt；
  3. 若没有保存过，则加载该语言族默认 prompt；
  4. 修复早期版本可能误写入的 stale 内置模板。

**验收标准**：

| 用例 | 期望行为 |
| --- | --- |
| 简体中文切到 English | prompt 编辑框显示英文模板 |
| English 切回简体中文 | prompt 编辑框显示中文模板 |
| 修改 English prompt 后切走再切回 | 保留 English 自定义内容 |
| 旧版本误把中文默认值写入 English 槽位 | 自动替换为 English 默认模板 |

---

### O27 — 目标语言切换后立即同步到 API 调用

**问题**：

用户启动时选择 English，之后在设置页切换到中文；如果运行时 Rust LLM 配置没有同步更新，下一次翻译仍会使用 English。

**需求**：

- 目标语言 Picker 变化后立即热更新运行中的 LLM 配置。
- 热更新内容包括目标语言、当前语言 prompt、Base URL、API Key、模型名和 System Prompt。
- 保存设置按钮继续可用，但语言切换不应依赖用户额外点击保存。

**验收标准**：

| 用例 | 期望行为 |
| --- | --- |
| English 切到简体中文后直接翻译 | 下一次 LLM 请求使用简体中文 |
| 简体中文切回 English 后直接翻译 | 下一次 LLM 请求使用 English |
| 点击保存设置 | 同样热更新当前配置并显示保存状态 |

---

### O28 — 翻译缓存按目标语言隔离

**问题**：

旧缓存 key 只包含 `word + sentence_hash`，没有目标语言。用户先用 English 翻译某个词，再切到中文翻译同一词同一上下文时，可能直接命中 English 缓存。

**需求**：

- 翻译缓存 key 增加 `target_language` 维度。
- 普通翻译和 streaming 翻译都必须使用当前目标语言读写缓存。
- 数据库 schema 增加 `translation_cache.target_language`。
- 旧数据库需要自动迁移，不丢失已有缓存数据。
- 迁移后允许同一 `word + sentence_hash` 在不同目标语言下保存多条缓存。

**验收标准**：

| 用例 | 期望行为 |
| --- | --- |
| English 下翻译并写入缓存 | cache key 包含 English |
| 切到简体中文翻译同一词同一句 | 不命中 English 缓存，重新请求并写入中文缓存 |
| 再切回 English | 可命中 English 缓存 |
| 老数据库升级 | `translation_cache` 自动增加语言维度且 App 可启动 |

---

### O29 — 主窗口尺寸和位置持久化

**问题**：

App 每次启动窗口大小不一定符合用户上次阅读习惯，需要重复调整。

**需求**：

- 关闭、移动、缩放窗口后保存主窗口 frame。
- 下次启动时恢复上次窗口大小和位置。
- 保留 macOS 原生 autosave 能力，同时手动保存关键窗口事件以提高可靠性。

**验收标准**：

| 用例 | 期望行为 |
| --- | --- |
| 调整窗口大小后关闭 App | 下次启动恢复该大小 |
| 移动窗口后关闭 App | 下次启动恢复该位置 |
| 实时缩放结束 | frame 被保存 |

## 兼容性与回归

- **Prompt 设置**：仅自动替换内置默认值或 stale 内置值；用户自定义 prompt 应按语言族保留。
- **数据库**：`translation_cache` 新增 `target_language` 并重建唯一键；旧缓存以空语言迁移保留，不丢数据，但新请求会按真实语言写入新缓存。
- **UniFFI API**：解释接口新增 `focus` 参数，Swift bridge 和 Rust API 必须同步更新。
- **缓存行为**：fallback 结果仍不写缓存；LLM 成功结果按目标语言写缓存。
- **UI 行为**：解释气泡限制不影响普通单词翻译气泡的基本展示。

## 不在本期范围内

- 为日文、韩文分别提供独立本地化 prompt（当前非中文目标默认使用英文 prompt）。
- 对旧 `translation_cache` 数据推断历史目标语言。
- 提供用户可配置的气泡最大比例。
- 对用户自定义 prompt 做语义检测或自动翻译。
