# LumenPDF — 选区标题误入与设置保存反馈 PRD

## 1. 产品结论

翻译原文必须对应用户真正高亮的正文。附近的小节标题即使措辞出现在段落里，只要没有被高亮，就不得进入原文、译文和拆解。设置保存失败必须在设置页底部保存栏用可读中文说明原因，不得再弹出主窗口中间的浮窗，也不得展示钥匙串状态码。当前发布包即使是 ad-hoc 签名、没有 Sandbox entitlement，也必须能保存 API Key；重新安装不能当成修复钥匙串权限的办法。

## 2. 问题

1. 用户只划了一段正文（例如以 “concurrency control” 收尾的句子），翻译浮窗原文却以未被高亮的小节标题 “Concurrency control” 开头。读者会以为选区错了。
2. 更新 API Key 后保存失败时，主阅读窗口中央弹出技术性浮窗（含钥匙串代码 `-34018`），设置页保存栏只写「保存失败」。失败发生在设置窗口，提示却跑到另一扇窗口，且看不懂下一步该做什么。用户按「重新安装」也无法保存：当前发布包没有 data-protection 钥匙串所需的 entitlement，重装不会补上。

## 3. 功能需求

### F1 — 未被高亮的小节标题不得进入选区文本

- 翻译原文、发给模型的选区、以及由此生成的拆解，只包含用户高亮的正文。
- 若某行像小节标题，且其词组已经出现在同一次选中的正文里，视为 PDF 选区泄漏，去掉该标题。
- 标题词组并未在正文中复述时，用户若同时选中标题和段落，两者都保留。
- 只选标题本身时，仍翻译该标题。

### F2 — 设置保存失败就地、可读

- 「保存设置」失败时，完整原因出现在设置页底部保存栏，替代「设置已保存」。
- 不得再向主阅读窗口发送保存失败或「LLM 配置已生效」的浮窗。
- 钥匙串写入失败用日常语言说明（例如无法写入钥匙串、或先解锁 Mac），不展示状态码或 “errSec” 一类术语，也不把「重新安装」当成修复办法。
- 提示词校验失败仍切到提示词分页，但同样只在保存栏展示原因。
- 保存成功仍只在保存栏显示「设置已保存」。

### F3 — ad-hoc 安装也必须能保存 API Key

- 当前发布包是 ad-hoc 签名且不附带 Sandbox / Keychain Sharing entitlement。在这种安装里，data-protection 钥匙串会返回缺少 entitlement，保存必须改写同一条 service/account 的普通钥匙串条目。
- 不附加 trusted-application ACL，不重新启用 App Sandbox，也不把 API Key 写入 `UserDefaults`。
- 重新安装同一类包不得再被提示为修复步骤。

## 4. 非目标

- 不保证 PDFKit 高亮矩形与内部字符范围在所有 PDF 上完全一致；只保证送给翻译的文本与可见高亮的正文一致。
- 不把 API Key 改为明文文件或 `UserDefaults`，也不为获得 entitlement 而恢复 App Sandbox。
- 不改变翻译降级链。

## 5. 验收标准

1. 高亮「Many systems … for concurrency control.」这类正文时，翻译原文不以「Concurrency control」开头。
2. 只选小节标题时，原文仍是该标题。
3. 在当前 ad-hoc 发布包中修改并保存 API Key 后，设置页显示已保存，完全退出再打开仍能读到该 Key。
4. 设置里若仍保存失败，保存栏出现可读失败说明；主阅读窗口不出现浮窗；不出现「设置已保存」；文案不含钥匙串状态码，也不要求重新安装。
5. 提示词校验失败时，保存栏显示校验原因，并停留在提示词分页。
