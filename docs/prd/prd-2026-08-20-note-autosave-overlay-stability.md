# LumenPDF — 笔记自动保存与翻译浮窗位置稳定 PRD

## 1. 产品结论

已有笔记必须能直接改、改完即存，不要显式保存按钮；保存成功后给出「保存成功」状态。翻译从加载变为完成、内容变高时，浮窗必须留在第一次出现的位置，不能换边闪跳。

本迭代落实 Inspector 笔记编辑，并回到 v1.0.15「加载到完成保持方向」的体验，优先于 v1.0.21「长高后改换边」的规则。

## 2. 问题

1. Inspector、原文回顾浮窗和笔记列表以只读 Markdown 展示笔记，修改路径不完整或依赖单独保存。
2. 翻译完成时页脚和正文同时变高，定位策略重新换边，窗口从选区下方跳到上方。

## 3. 功能需求

### F1 — 可编辑笔记

- 阅读 Inspector 笔记卡、原文笔记回顾浮窗、笔记列表均可直接编辑对应条目。
- 原文划线文本本身不可改。
- 同一选区多条笔记按条编辑，互不影响。

### F2 — 自动保存

- 停止输入约 450ms 后写入；失焦或视图消失时若有未保存改动立即写入。
- 不提供显式「保存」按钮。
- 写入成功后显示「保存成功」状态；下一次修改时隐藏，再次成功后再出现。
- 失败时显示「保存失败」，不覆盖已存内容。
- 空白（trim 后为空）不写入，避免把已有笔记存成空。

### F3 — 新建笔记仍需确认

- 添加/追加笔记草稿仍使用显式保存，空内容不可提交。本迭代不把新建草稿改成自动保存。

### F4 — 翻译浮窗位置固定

- 浮窗首次测量后锁定左上角原点。后续修订：翻译改为系统 `NSPopover`，锁定的是首次箭头边而不是 overlay 原点，见 [prd-2026-09-01-native-translation-popover.md](prd-2026-09-01-native-translation-popover.md)。
- 之后内容变高只向下增高，并用容器边界做最小钳制。
- 不得因为可能挡住选区就改到上方、左侧或右侧。
- 用户拖动后仍以拖动位置为准；新的翻译会话重新定位。后续修订：翻译弹出层不再拖动。

## 4. 非目标

- 不改笔记 JSON 存储格式。
- 编辑时不要求实时渲染 Markdown 预览。
- 不改变选区操作栏的首次定位优先级（仍为下、上、右、左）。

## 5. 验收标准

1. 在 Inspector、回顾浮窗、笔记列表修改一条笔记，停顿后出现「保存成功」；再打开或刷新后内容仍在。
2. 没有单独的保存按钮。
3. 清空输入不会把原笔记存成空。
4. 选中单词翻译：加载态浮窗位置在翻译完成后保持不动，不跳到选区另一侧。
5. 拖动、点外关闭、窗口缩放后的边界限制仍可用。
