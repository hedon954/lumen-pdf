## O18 — DMG 版本同步

### 设计

`package-dmg.sh` 新增 `INFO_PLIST="$XCODE_DIR/Info.plist"`，打包开始时读取：

```bash
PLIST_VERSION="$(/usr/libexec/PlistBuddy -c "Print :CFBundleShortVersionString" "$INFO_PLIST")"
VERSION="${VERSION:-$PLIST_VERSION}"
DMG_PATH="$BUILD_DIR/${APP_NAME}-${VERSION}.dmg"
```

### 原则

- 默认以 `CFBundleShortVersionString` 作为公开发布版本的单一事实来源。
- `CFBundleVersion` 是内部 build number，不进入 DMG 文件名和普通日志展示。
- 保留环境变量覆盖，避免阻断临时构建。
- 只改变产物命名和日志，不改变 archive / export 流程。

### 风险

`Info.plist` 缺失 key 时脚本会在 `set -e` 下失败。这是合理失败，因为版本元数据不完整时不应产出发布包。

## O19 — 本机升级脚本

### 入口

`Makefile`：

```make
upgrade: dmg
	./scripts/upgrade-local.sh
```

通过依赖 `dmg`，确保安装前一定完成 Rust release dylib、UniFFI 绑定、Xcode archive/export 和 DMG 制作。

### 安装来源

升级脚本不挂载 DMG，而是直接使用 `package-dmg.sh` 已经导出的：

```bash
SOURCE_APP="$ROOT_DIR/build/export/LumenPDF.app"
TARGET_APP="/Applications/LumenPDF.app"
TMP_TARGET="/Applications/LumenPDF.app.tmp.$$"
```

这样少一次磁盘镜像挂载，也避免反向从 DMG 拷贝造成额外状态。

### 进程终止策略

```bash
pgrep -x "LumenPDF"
kill <pids>
wait up to 4s
kill -9 <pids>
verify no pid remains
```

先给应用正常退出机会；如果窗口或 run loop 卡住，再强制终止。强制终止后仍存在 pid 则退出，避免替换正在使用的 bundle。

### 安装策略

```bash
ditto "$SOURCE_APP" "$TMP_TARGET"
rm -rf "$TARGET_APP"
mv "$TMP_TARGET" "$TARGET_APP"
xattr -dr com.apple.quarantine "$TARGET_APP"
```

使用临时目录是为了避免 `ditto` 中途失败时破坏原有 `/Applications/LumenPDF.app`。`trap` 会清理临时目录。

### 权限策略

所有写 `/Applications` 的命令走 `run_for_applications`：

```bash
if [ -w "/Applications" ]; then
    "$@"
else
    sudo "$@"
fi
```

这让普通开发机和需要管理员权限的机器都能使用同一入口。

## O20 / O21 — 笔记渲染与原文归一化

### 原文归一化函数

`ContextSentenceFormatting.displayParagraph` 负责把 PDFKit 文本流转换为适合阅读的段落：

```swift
raw
    .replacingOccurrences(of: "\r\n", with: "\n")
    .replacingOccurrences(of: "\r", with: "\n")
    .replacingOccurrences(
        of: #"([A-Za-z])-\s*\n\s*([A-Za-z])"#,
        with: "$1$2",
        options: .regularExpression
    )
    .split(whereSeparator: { $0.isWhitespace || $0.isNewline })
    .filter { !$0.isEmpty }
    .joined(separator: " ")
```

该函数的职责边界很窄：只处理 PDF 文本流带来的排版噪声，不参与笔记正文、模型解释或用户输入的改写。

### 入库点

在 `BridgeService.saveNote` 统一处理：

```swift
let normalizedContent = ContextSentenceFormatting.displayParagraph(content)
return try _saveNote(SaveNoteRequest(... content: normalizedContent ...))
```

选择桥接层而不是各调用点，是为了覆盖：

- 划线保存
- 解释保存到笔记
- 撤销 / 重做恢复笔记
- 未来新增的保存入口

### 展示点

`NoteListView` 增加 `displayContent`，卡片和编辑弹窗都展示归一化内容。搜索也改用归一化后的 `content`，修复旧数据里硬换行导致正常句子搜不到的问题。

### MarkdownText 复用

原本 `MarkdownText` 是 `TranslationBubble.swift` 的私有组件，本次改为模块内可见：

```swift
struct MarkdownText: View { ... }
```

`NoteCardView` 对 `note.note` 使用它渲染，避免笔记页展示 Markdown 源码。

## O22 — LLM 解释输出策略

### Token 上限

`ChatRequest` 新增：

```rust
#[serde(skip_serializing_if = "Option::is_none")]
max_tokens: Option<u32>,
```

统一常量：

```rust
const DEFAULT_MAX_TOKENS: u32 = 4096;
```

以下请求都会设置 `max_tokens`：

- 选区解释
- 整句翻译
- 单词翻译
- 单词流式翻译

虽然用户主要反馈选区解释被截断，但统一设置可以避免不同路径表现不一致。

### 超时

`shared_client()` 总请求超时从 30s 调整到 120s：

```rust
.timeout(Duration::from_secs(120))
```

连接超时仍保持 3s，避免网络不可达时等待过久；总超时只给已建立连接后的长输出更多空间。

### Prompt 去长度化

默认解释 prompt 从“强 Markdown / 短段 / concise takeaway / 不要 shorten”改为只描述解释任务：

```text
1. Start from first principles...
2. Explain what the selected text means...
3. Explain why the author says this here...
4. Mention key terms...
5. Preserve real line breaks between distinct ideas and blocks.
6. Prefer a layered explanation...

Return ONLY the explanation text...
```

这里刻意不要求“长”、不要求“短”、不要求固定 Markdown 层级，模型可以按上下文自行决定展开方式。

### 设置迁移

`SettingsView.migratePromptDefaultsIfNeeded` 只在当前值等于旧默认值时迁移：

```swift
if explanationPromptTemplate == legacyExplanation
    || explanationPromptTemplate == legacyMarkdownExplanation
{
    explanationPromptTemplate = PromptTemplateDefaults.explanation
}
```

用户自定义 prompt 不会被覆盖。

### 前端渲染去重排

`MarkdownText.normalizedMarkdown` 以前包含多条正则，用于强行在标题、列表、加粗词前插空行。本次全部移除，只保留：

```swift
markdown
    .replacingOccurrences(of: "\r\n", with: "\n")
    .replacingOccurrences(of: "\r", with: "\n")
    .trimmingCharacters(in: .whitespacesAndNewlines)
```

这保证前端不再主动“修复”或改写模型结构。

## O23 — 翻译气泡顶部换行

### 问题

选区解释模式下，顶部 header 左侧文本和右侧控制按钮处在同一个 `HStack`，长选区可能被挤成窄列。

### 方案

```swift
Text(ContextSentenceFormatting.displayParagraph(request.result?.word ?? request.word))
    .lineLimit(nil)
    .fixedSize(horizontal: false, vertical: true)

VStack(...)
    .frame(maxWidth: .infinity, alignment: .leading)
    .layoutPriority(1)
```

关键点：

- header 文本先做 PDF 原文归一化
- 左侧 `VStack` 主动占满可用宽度
- `layoutPriority(1)` 降低被右侧按钮过度挤压的概率
- 不设置截断，让 SwiftUI 自然换行

## 回归风险与观察点

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 某些 OpenAI-compatible 网关不支持 `max_tokens` | 请求可能返回参数错误 | 错误按现有 LLM 错误路径展示；后续可做 provider-specific 配置 |
| 120s 超时让失败等待变长 | 已连上但上游迟迟不返回时，等待时间变长 | 连接超时仍为 3s；长等待主要发生在已开始生成或网关卡住场景 |
| MarkdownText 不再正则修复 | 模型输出如果本身格式差，前端不再代修 | 符合“直接展示模型输出”的产品原则 |
| 新保存的 note content 被归一化 | 原始 PDF 排版换行不再保留 | 该字段用于阅读展示，不用于 annotation 定位；boundsStr 保持不变 |
| `make upgrade` 强制 kill | 正在运行的 app 未保存 UI 临时状态可能丢失 | 这是本机开发升级工具，目标就是替换运行中的版本 |
